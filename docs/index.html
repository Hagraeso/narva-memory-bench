Does agent memory beat plain retrieval?

We ran Mem0 and Graphiti, a plain vector search over the raw conversation, and the whole conversation in the context window through one protocol on all of LoCoMo: 10 long conversations, 1,540 questions, every answer graded by the same stronger model. Neither memory system beat the plain search, and putting the whole conversation in the window beat everything by a wide margin.

The result

The two memory systems do more work at write time than the plain search: they send every session through a language model, extract facts, and store those facts instead of the words. On this benchmark that work lost information. Both systems answered "not mentioned" more often than the plain search (Mem0 470 times, Graphiti 412, plain search 347), so facts that were in the conversation did not survive extraction. The whole conversation in the window said "not mentioned" only 83 times.

Where the information goes

A dating defect in Mem0 open source

On questions about time, Mem0 answered 38.6% correctly against 63.5% for the plain search, and 82 of its 321 time answers named 2026, the year we ingested the data. The conversations took place in 2022 and 2023. Neither the plain search nor Graphiti made that mistake once.

Leaving time questions out does not rescue Mem0: on the other 1,219 questions it still trailed the plain search by 12.2 points (interval −15.4 to −9.0). Graphiti trailed by 11.3 on the same questions (−14.6 to −8.2), even though it matched the plain search on time questions (65.7% against 63.5%).

What this means for builders

  • If the history fits in the model's context window, put all of it in. The largest prompt here was 30,892 tokens. It costs about 39 times the tokens of retrieval per question, and it was 19 points more accurate.
  • Keep the raw text. Extracting facts at write time lost more than it gained here; a plain search over the original turns beat both extraction systems.
  • Test time questions on your own data before trusting dates from Mem0 open source on past conversations.
  • Treat published vendor scores as unconfirmed outside their own setups. Mem0's own paper reports full context ahead of Mem0 too (72.9% against 66.9% with its setup); the gap we measured is larger.

How it was measured

  • Pre-registered. The spec (DOM-01-phaseB-v2.1, sha256 fc83e666…a547) fixed models, prompts, statistics and verdict rules before the run. Code refused a full run until a small smoke run with the same spec and code had passed.
  • Same everything. One answer prompt and one answer model (gemini-3-flash-preview, low thinking) for all four systems; each memory system used the same model internally. Every answer was graded by gemini-3.1-pro-preview against the LoCoMo answer key.
  • Statistics. Paired differences per question, 95% percentile bootstrap, 10,000 resamples, seed 0. A verdict of better or worse needs the whole interval on one side of zero.
  • Versions. mem0ai 2.2.1 (each session added whole, dates inside the text); graphiti-core 0.31.2 on FalkorDB (each session one episode with its date as reference time, 10 facts returned with their valid dates). The vector search returns 10 raw turns by text-embedding-005.
  • Disclosed repairs. 18 grades came back empty (the judge spent its output cap on thinking) and were asked again with the same judge and a larger cap; 9 were then correct. No failed answer was scored. Ingest of the first 3 conversations was reused from an earlier run with identical settings after a check that the stored data was complete.
  • Cost. About 616 SEK of metered model calls for the full run, on Google's discounted Flex tier.

Limits

  • One dataset, English only. Every conversation fit in the context window, so this says nothing about histories that do not; that is where a memory system has to earn its place, and it is our next test.
  • Two memory systems, both open source. Mem0's hosted platform and its newer published algorithm were not tested.
  • Each system ran under our shared protocol, not its vendor's own evaluation recipe.
